# CRM «Процедурный кабинет»: реализация ТЗ 3.0

Одна база Supabase, персональный вход сотрудников, статический сайт Render. Новая версия интерфейса — 5; это внутренняя версия кода, а не изменение ТЗ.

| Раздел ТЗ | Реализация |
| --- | --- |
| Пациенты | Достаточно имени; необязательные дата рождения, пол, телефон, комментарии и назначения. История процедур/покупок, фото и PDF. Владелец редактирует и архивирует; архив сохраняет историю. |
| Процедуры | Пациент, действующая услуга, редактируемый шаблон либо повтор прошлой процедуры. Текущие цены, проверка годного рабочего остатка, одно атомарное сохранение с оплатой и списанием. |
| Голос | Русская речь или текстовая команда. Результат можно исправить. Предпросмотр и подтверждение заполняют форму или поиск. Сохранение процедуры остаётся явным действием. |
| Склад | Запас только владельцу; годный рабочий остаток доступен медсестре. Карточки, фото, упаковки, партия, номер, поставщик, приход, перенос, возврат, списание, инвентаризация с причиной. FEFO по годным партиям. |
| Продажа | Отдельно от процедуры. Медсестра расходует рабочий остаток. Владелец может явно разрешить продажу недостающего количества из запаса; перенос и продажа выполняются в одной транзакции. |
| Услуги/шаблоны | Владелец управляет справочниками; медсестра использует действующие записи и корректирует состав черновика. |
| Смены | Две смены в день, две разные активные медсестры. Личные логины. Повтор открытия возвращает ту же открытую смену; пересечение работников запрещено. |
| Зарплата | Новая смена — 2 000 ₽ каждому сотруднику независимо от процедур. Ручное изменение только владельцем с причиной и аудитом. Историческая неизвестная зарплата не выдумывается. |
| Касса | Наличные, терминал, карта владельца, смешанная оплата. Сумма частей равна оплате. Полученные наличные и сдача не увеличивают выручку. Разменный фонд отдельно. |
| Закрытие | Сохраняется снимок отчёта: сотрудники, пациенты, процедуры, продажи, расход, остатки и предупреждения. Владелец также видит распределение выручки и зарплату. |
| Отчёты | Даты, смена, день, месяц, сотрудник, пациент, препарат, услуга, склад; печать/PDF и CSV. Складской отчёт: движения за период по Москве с фильтром препарата, текущие остатки отдельно, CSV и печать. Денежный остаток — выручка минус зарплата, без названия «прибыль». |
| Аналитика | Пациенты и процедуры за период, выручка, денежный остаток, складские остатки, минимум и сроки годности. |
| Безопасность | Серверные проверки роли/активности, RLS, закрытые документы и копии, персональный аудит, защита от повторного запроса и прямого обхода записи. |
| Обновления | Render публикует код из main. Интерфейс проверяет новую версию; применяет её на свободном экране, а при открытом черновике предлагает сохранить работу перед обновлением. |
| Резервные копии | Ежедневно в 03:15 Москвы: согласованный JSON-снимок данных и копии PDF/изображений, SHA-256, отметка завершения. Закрытое Storage, хранение 7 дней. Владелец может запустить и проверить копирование. |

## Принятые правила

- Время кабинета — Москва (UTC+3), одинаковое на любых устройствах.
- Медсестра вводит оплату текущего пациента, но не видит финансовую аналитику, общую выручку или зарплатные данные. Её отчёт закрытия содержит рабочие итоги.
- Повтор и шаблон заполняют редактируемый черновик. Исторические цены, скидки и прежняя оплата не переносятся.
- Количество задаётся в единице списания карточки целыми единицами. Для объёмов можно использовать единицу «мл». Программа не рассчитывает врачебные назначения и не преобразует дозировки автоматически.
- Старые платежи без известного способа отображаются как нераспределённые. Зарплата прошлой смены без сохранённого значения требует ручного ввода владельцем с причиной; денежный остаток до этого не рассчитывается.
- Финансовый результат пациента/услуги/препарата не вычитается из всей зарплаты кабинета. Общий денежный остаток относится к периоду кабинета.
- Архивирование сохраняет записи. Отмена сохранённой процедуры, возврат денег и восстановление резервной копии не выполняются скрыто или автоматически.

## Возможности браузера

Интерфейс работает через HTTPS на телефонах и компьютерах. Голосовое распознавание зависит от поддержки браузером и разрешения микрофона; при отсутствии поддержки доступна текстовая команда. Файлы открываются по краткоживущим подписанным ссылкам. Данные пациентов не сохраняются в localStorage; браузер хранит только сессию авторизации Supabase.

## Копирование и восстановление

Автоматическая копия содержит клинические таблицы, партии/движения, идемпотентные запросы, платежи, зарплату, отчёты закрытия, настройки, шаблоны, аудит и избранное. Документы и фото копируются вместе с манифестом исходных путей и SHA-256. Пароли, токен задания и Vault в выгрузку не входят.

Это логическая копия данных и документов. Для восстановления на новом проекте сначала применяют исходную схему и миграции, затем восстанавливают связанные таблицы по внешним ключам и файлы по манифесту. Учётные записи Auth восстанавливаются отдельно. Проверять восстановление следует в отдельном проекте; импорт не перезаписывает рабочую базу через интерфейс.

## Проверки

`npm test` проверяет расчёты оплаты и сдачи, повтор запроса, сохранение формы при ошибке, права интерфейса, поиск, шаблоны, голосовые команды и безопасный вывод. SQL-файлы `db/crm-*-v5-test.sql` выполняются в транзакции с `ROLLBACK`. Браузерные проверки используют вымышленную базу, проверяют экран телефона и рабочие сценарии. Производственные документы и карточки не используются как тестовые примеры.
