## CRM по ТЗ 3.0

Начало работы: [docs/START.md](docs/START.md). Подробные правила и проверяемый объём: [docs/CRM-TZ-3.0.md](docs/CRM-TZ-3.0.md).

Supabase SDK 2.117.2 закреплён и хранится в `vendor/`: вход не зависит от доступности внешнего CDN. `npm ci && npm test` запускает проверки; браузерные сценарии — `npm run test:browser`. Все тестовые данные вымышлены.

Миграции v5: управление → финансы → склад → резервное копирование → складской отчёт. После публикации интерфейса отдельная активация закрывает старые API записи без распределения оплаты. Каноническая миграция сохранена в `supabase/migrations/`. Edge Functions `crm-admin` и `crm-backup` выполняют собственную проверку доступа; их серверные ключи не отправляются в браузер.

Автоматическая копия включает данные и файлы, выполняется в 03:15 Москвы, хранится 7 дней в закрытом Storage. Владелец видит состояние последнего запуска и может создать копию вручную. Процедура восстановления и ограничения голосового распознавания описаны в документе реализации.

Проверено 07.10.2026: основные SQL-сценарии в транзакции с откатом, семь модульных наборов и восемь браузерных сценариев на ширине 390 px. Проверки без авторизации возвращают 401. Первая полная резервная копия успешно завершена. Восстановление в отдельном проекте ещё не проверялось.

Версия 5.1 добавляет заметную кнопку «Исправить количество»: владелец корректирует остаток выбранной партии или число единиц в упаковке с причиной и подтверждением. ## Быстрый интерфейс v4

На главном экране пять действий: новый пациент, новая процедура, продажа, пациенты и склад. Меню сотрудника содержит смену, отчёт и выход. Для процедуры или продажи требуется открытая смена; администратор может выбрать открытую смену нужной пары сотрудников.

Поиск по русскому/латинскому названию, МНН, дозировке и категории меняет только каталог, не очищая выбранные строки. Крупные фото дополнены обязательными читаемыми названиями и дозировками. Звёздочка сохраняет избранное для текущей учётной записи в базе; остальные препараты сортируются по частоте использования за последние 30 дней. Повторное нажатие на препарат увеличивает количество в выбранной строке.

В карточке пациента показана последняя процедура. «Повторить» создаёт только черновик: использует текущую смену, текущие цены и проверяет рабочий остаток. Исторические скидки, оплату и комментарии не переносит. Отсутствующие/архивные препараты и недоступная услуга требуют исправления перед сохранением. Программа не создаёт медицинских назначений.

Медсестра видит только рабочий шкаф и цены продажи. Запас, партии запаса, закупочные цены и переводы доступны только admin/owner. При нехватке в черновике медсестра видит просьбу обратиться к администратору; администратор может перевести целое количество упаковок. На складе доступны карточки быстрого пополнения одной упаковкой. Метаданные препарата свернуты, поэтому приход сразу открывает количество упаковок, цену и срок годности. Начальные остатки в отдельных единицах сохранены для первого заполнения вскрытых коробок.

Отчёт показывает пациентов, процедуры, полученную оплату и расход каждого препарата отдельно на процедуры и продажи. Кнопка завершения закрывает смену и оставляет итог на экране. Повторное открытие той же пары сотрудников возвращает существующую смену; пересечение пары с другой открытой сменой запрещено. Голосовой ввод в v4 не добавлен.

Миграции этой версии: `db/quick-ui-v4.sql`, затем `db/service-shift-v4.sql`. Они применены на рабочей базе. Новые точки API проверяют активного сотрудника и роль; приватное избранное не доступно напрямую. Прежние рабочие записи сохраняются.

Проверки v4: `node tests/quick-ui.test.cjs`, прежние две Node-проверки, `db/quick-ui-v4-test.sql` и `db/shift-v4-test.sql` целиком с ROLLBACK. Проверены изоляция избранного, отсутствие доступа медсестры к запасу/закупкам, повтор процедуры, точная ссылка на услугу, отчёт, повтор открытия и пересечение смен. Браузерный сценарий с подставной базой: поиск по категории без потери строки, избранное, повтор, оплата 600 ₽, сохранение, расход 1 и 2 единиц, отчёт и закрытие. Для администратора проверены быстрый перевод упаковки и подсказка внутри процедуры. Ширины 390 и 1280 пикселей — без горизонтального переполнения. Медицинские документы и голосовой ввод не входят в проверенный объём.

Статическое приложение на Render, данные и авторизация — Supabase.

## Как вести препараты

1. Создать карточку: название, ампул/флаконов в целой упаковке, закупочная цена упаковки, цена одной единицы для пациента. Сохранение карточки само по себе не создаёт остаток.
2. В карточке раскрыть «Внести имеющиеся остатки». Указать фактическое число единиц, место хранения и срок годности. Например, вскрытая коробка 75 из 100 — количество 75. Остаток рабочего шкафа внести отдельно, выбрав «В рабочем шкафу». Разные сроки — отдельными операциями. Не вносить одну партию повторно.
3. Последующие целые упаковки принимать через «Приход новой закупки» — они поступают в запас.
4. При физическом перемещении со склада в шкаф использовать «Перевести из запаса в рабочий шкаф». Можно указать отдельные единицы или целые упаковки. Это перемещение, а не расход.
5. Медсестра указывает использованные единицы в процедуре либо продаже. Списание происходит один раз при успешном сохранении, только из рабочего шкафа. Раньше расходуется годная партия с ближайшим сроком.
6. Для возвращения ампул на склад использовать возврат. Потерю, повреждение и просрочку оформлять списанием с выбором партии, места и причины. Расход на процедуру повторно не списывать.

Карточка показывает запас, рабочий шкаф, общий остаток, годное количество, партии и историю. Архивирование возможно только при нулевом остатке и сохраняет историю. Единицу расхода и размер упаковки при ненулевом остатке менять нельзя.

## Версия учёта 3

`index.html` загружает `warehouse-v3.js`, `workflow-v3.js` и `warehouse-v3.css`. Версионные имена обходят старый кэш. `warehouse.js` — идентичная исходная копия складского модуля.

`db/stock-lifecycle.sql` вводит распределение партий по местам хранения, атомарное списание и идентификаторы повторных запросов. Это одноразовая миграция после v2.1; она требует отсутствия прежних ненулевых остатков, иначе останавливается для сверки. На рабочей базе применена 30.09.2026 после проверки нулевых остатков двух карточек. `db/stock-permissions.sql` закрывает старые обходные точки записи. Не выполнять повторно первоначальные миграции поверх новой версии.

Количество хранится в целых единицах расхода. Для партии запас = quantity_remaining − work_quantity. Суммы партий сверяются с таблицей stock после каждого движения. Перевод не меняет общий остаток; расход и списание уменьшают его. Блокировки препарата, партий и смены обеспечивают атомарность. Неудачная операция полностью откатывается. Идентификатор запроса защищает повтор после потери ответа в открытой форме; после успешного ответа поля очищаются. Успешное сохранение с прежним количеством, введённым заново, считается новой операцией.

## Проверки

`node tests/warehouse.test.cjs`

`node tests/workflow.test.cjs`

`db/lifecycle-test.sql` выполняется целиком, включая BEGIN и ROLLBACK. Проверяет карточку, приход, остатки обоих мест, перевод, процедуры, продажи, повтор запросов, объединение одинаковых строк, стоимость и скидку, доступ ролей, партии, просрочку, возврат, списание, отчёт и закрытую смену. Тестовые записи откатываются. Требуются действующие сотрудники admin/owner и nurse; новые учётные записи не создаются.

Формы ввода 75 отдельных единиц, перевода 10 и возврата 3 проверены в браузере с подставной базой. Рабочие количества пользователя не менялись. Перед началом работы пользователь заполняет реальные остатки и свой прайс; нулевые цены не заменяются выдуманными значениями.

Проверка этой версии охватывает учёт препаратов и связанные процедуры/продажи/отчёт. Загрузка медицинских документов, расчёт зарплаты и полная проверка всех ролей не входят в проведённый тест. Supabase сообщает о существующих защищённых SECURITY DEFINER RPC и выключенной проверке утёкших паролей; отдельная проверка настроек Auth остаётся необходимой: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection .
