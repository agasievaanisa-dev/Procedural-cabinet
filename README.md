# Процедурный кабинет: склад 2.0

Обновление существующего приложения. Остатки в базе по-прежнему хранятся в единицах расхода, без пересчёта старых данных.

## Что изменено

- Карточки показывают упаковки и отдельные единицы в запасе, рабочий остаток и общий итог.
- Поиск по названию, МНН, дозировке, производителю и категории; фильтры пополнения, заказа, сроков и архива.
- Приход партии с проверкой количества, цены и срока; перевод упаковок или отдельных единиц.
- Исправлен тип движения: `reserve_to_work` вместо несуществующего `transfer_to_work`.
- Серверные операции выполняются атомарно, блокируют строку препарата и используют идентификатор запроса для безопасного повтора после потери ответа.
- История последних 100 движений, партии, архивирование пустых карточек и восстановление.
- Фото сохраняется существующим механизмом Storage; карточка явно сообщает о частичном сбое загрузки фото.
- Новый каталог медсестры содержит только активные препараты с положительным остатком в работе, без закупочных цен и резерва.

## Публикация

1. Сохранить резервную копию базы стандартными средствами проекта.
2. Применить `db/warehouse-v2.sql` в Supabase **до** публикации интерфейса. Скрипт транзакционный; не меняет существующие остатки. Требуется существующая схема приложения с функциями `private.is_manager`, `manager_set_medication_test` и `manager_inventory_photo_v1`.
3. Опубликовать `index.html`, `warehouse.js`, `warehouse.css` вместе через существующий сервис Render.
4. Проверить вход владельца и медсестры, список, фото, приход и перевод на согласованной тестовой карточке.

Возврат предыдущего фронтенда возможен без удаления данных: прежний RPC перевода сохранён совместимым. Не удалять таблицу идентификаторов операций для отката.

## Проверки

`node tests/warehouse.test.cjs`

Проверяет пересчёт, общий остаток, даты, фильтры, экранирование названий, валидацию, повтор запроса после потери ответа и синтаксис встроенных скриптов.

Для теста SQL объединить содержимое `db/warehouse-v2.sql` **без последнего COMMIT** с `db/warehouse-v2-test.sql` и завершить `ROLLBACK`. Нужны активные сотрудники admin/owner и nurse, связанные с Auth. Тест не создаёт пользователей и не обращается к пациентам. Проверяет приход, повтор запроса, перевод, запрет превышения остатка, просроченного прихода, архива с остатками, доступ медсестры и запрет анонимного вызова. Не запускать тестовый файл отдельно с фиксацией изменений.

SQL-проверки проведены в транзакции с откатом; после теста подтверждены исходные 1 карточка и нулевые остатки. Интерфейс проверен отдельно с подставной базой, без операций в рабочей базе.

## Границы этого обновления

Партии учитываются общим остатком: распределения каждой партии между запасом и рабочим шкафом пока нет. Даты отображаются и подсвечиваются, но это не подтверждение пригодности препарата. Списание по процедурам использует прежние серверные функции и требует отдельной доработки для учёта конкретной партии по месту хранения.

Пациенты, финансы, способы оплаты, расчёт выплат и отчёты смены не переработаны. Существующие предупреждения Supabase по другим RPC/Auth остаются отдельной задачей. Полная готовность приложения к реальным медицинским данным этим обновлением не подтверждается.

Массовый импорт пока использует прежний RPC. Проверка реальной загрузки фото и входа после публикации требует рабочего сеанса пользователя; пароли для этого передавать не нужно.
